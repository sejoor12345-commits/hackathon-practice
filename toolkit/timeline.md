# 시간표 – 24시간 / 48시간 / 2주

> 공통 규칙: **마지막 25%는 만들기에 쓰지 않는다** (영상·README·피칭). 배포 주소는 첫 25% 안에 확보한다.
> 사지방 기준: 한 번에 쓸 수 있는 시간이 짧다면 아래 "블록"을 하루 1~2개씩 나눠서 한다.

## 24시간 해커톤

| 시각 (시작 기준) | 할 일 | 끝났다는 증거 |
|---|---|---|
| 0h–1h | 채점표(rubric) 읽기, `01-problem.md` | 한 문장 요약에 숫자 1개 |
| 1h–2h | `02-scope.md`, `03-criteria.md` | 안 만들 것 3개, 기준 3개 |
| 2h–3h | `starter/` 복사 → Vercel 배포 | 배포 주소가 열린다 |
| 3h–12h | 핵심 흐름 1개 만들기 (가짜 데이터 OK) | 처음부터 끝까지 한 번 돌아간다 |
| 12h–15h | 검증: 숨긴 입력 5개로 기준 판정 | 03 표에 예/아니오 |
| 15h–18h | 고치기 (기준에 걸린 것만) | 다시 판정 |
| **18h–22h** | 영상 녹화(`04-demo.md`), README, Devpost 글 | 영상 링크 |
| 22h–24h | 제출, 피칭 연습(`pitch-timer.html` 3회) | 제출 완료 화면 |

## 48시간 해커톤

| 시각 | 할 일 |
|---|---|
| 0h–3h | 문제·범위·기준 (위 24시간의 0h–2h를 천천히) + 사용자 1명에게 문제 확인 |
| 3h–5h | 배포 뼈대 |
| 5h–24h | 핵심 흐름 1개 끝까지 |
| 24h–30h | 검증 + 고치기 |
| 30h–36h | 두 번째로 중요한 것 1개만 추가 (선택) – 안 해도 됨 |
| **36h–46h** | 영상·README·피칭 |
| 46h–48h | 제출, 여유 시간 |

## 2주 (온라인 해커톤 / 창업경진대회 서류)

| 날짜 | 할 일 | 산출물 |
|---|---|---|
| 1일 | 공고·평가표 읽기, 자격 확인(병사 참가 가능? 팀 인원? 사업자등록?) | 확인 메모 |
| 2일 | 문제 카드 + 사용자 3명에게 물어보기 | `01-problem.md` (실측 숫자 1개 이상) |
| 3일 | 범위·기준 | `02`, `03` |
| 4–8일 | 만들기 (하루 1블록) + 매일 커밋 | 배포 주소 |
| 9일 | 숨긴 평가 세트로 검증 | 결과 표 |
| 10일 | 고치기 | |
| 11일 | 영상 대본 + 녹화 | YouTube 링크 |
| 12일 | README·사업계획서(`psst-cheatsheet.md`) | 제출 문서 |
| 13일 | 피칭 3회 + 질문 연습 10개 | pitch-timer 기록 |
| 14일 | 제출 (마감 하루 전) | 제출 완료 화면 |
