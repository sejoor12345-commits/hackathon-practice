# 02. 범위 줄이기

> "기능 1개"가 아니라 **"핵심 흐름 1개를 얇게 끝까지"** (practice_01 2회차 배움).
> 데모에 안 나오는 것은 가짜로 처리해도 된다. 대신 **무엇이 가짜인지 적는다.**

## 핵심 흐름 1개 (입력 → 판단 → 출력)

| 순서 | 사용자가 하는 일 | 시스템이 하는 일 | 진짜/가짜 |
|---|---|---|---|
| 1 | | | |
| 2 | | | |
| 3 | | | |

## 만들 것 / 안 만들 것

| 만들 것 (최대 3개) | 왜 꼭 필요한가 (데모에 나오나?) |
|---|---|
| | |

| 안 만들 것 | 대신 어떻게 (가짜 데이터, 손으로, 다음 버전) |
|---|---|
| 로그인 | 사용자 1명 고정 |
| 결제 | 화면에 "다음 버전" 표시 |
| | |

## 시간 예산 (전체의 비율)

| 일 | 비율 | 시간 |
|---|---|---|
| 문제·범위 | 10% | |
| 만들기 | 50% | |
| 검증 | 15% | |
| 영상·README·피칭 | **25%** (마지막 단계에서 멈추지 않도록 미리 떼어 둔다) | |

## 자가 점검
- [ ] 핵심 흐름이 5단계 이하다
- [ ] "안 만들 것"이 3개 이상 적혀 있다
- [ ] 가짜로 처리한 부분이 표에 표시돼 있다
- [ ] 마지막 25% 시간은 만들기에 쓰지 않기로 정했다
