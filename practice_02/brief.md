# practice_02 연습 문제 – 요구가 서로 부딪히는 교대근무표

> 모든 인물·기관·메시지는 **가짜**입니다. 군 내부 정보는 쓰지 않습니다.
> practice_01보다 어렵게: **이해관계자가 여럿이고 요구가 충돌**합니다 (practice_01 log "다음에 할 것").
> 이 문제는 풀려 있지 않습니다. 류지웅 님이 푸는 문제입니다.

## 상황 (연습 설정)

가짜 요양원 "해솔요양원" 원장은 매주 직원 7명의 3교대 근무표를 짭니다. 직원들은 단체 채팅방에 제각각 요청을 남기고, 보호자 연락도 원장에게 옵니다. 요청끼리 부딪히는데 원장은 누가 무엇을 양보해야 하는지 매번 손으로 따져 봅니다.

| 연습 설정 숫자 | 값 | 구분 |
|---|---|---|
| 직원 수 | 7명 | 데이터 (`data/staff.csv`) |
| 이번 주 요청 메시지 | 8건 | 데이터 (`data/requests.md`) |
| 원장이 근무표 짜고 고치는 시간 | 주 3시간 | **[가설]** 연습 설정. 실제로 잰 값 아님 |

## 파일과 여는 순서

| 파일 | 언제 여나 |
|---|---|
| `brief.md` (이 파일) | 처음 |
| `data/rules.md`, `data/staff.csv`, `data/last_week.csv`, `data/requests.md` | 1회차부터 |
| `answers.md` | **4회차 4-2에서 질문을 다 만든 뒤** |
| `eval_hidden/` | **4회차 4-3 검증 때만**. 그 전에는 사람도 AI도 열지 않음 |

AI에게 시킬 때 첫 줄에 꼭: "practice_02 폴더에서만 작업하고, answers.md 와 eval_hidden/ 은 내가 말하기 전까지 열지 마."

## 이번에 만들지 않을 것
- 로그인, 여러 주 달력, 직원용 앱, 알림 보내기
- "최적" 근무표를 찾는 복잡한 알고리즘 (근무표 1개 + 왜 그렇게 했는지 설명이면 충분)

---

## 1회차 – 문제 정의 (20점)

`toolkit/templates/01-problem.md`를 `practice_02/work/01-problem.md`로 복사해서 채웁니다.

| 채점 항목 | 점수 |
|---|---|
| 한 문장 요약에 누가·언제·손해가 있고 숫자가 1개 이상 | 5 |
| 불편함과 손해를 구분했다 | 5 |
| 이해관계자(원장·직원·보호자)마다 원하는 것을 한 줄씩 적었다 | 5 |
| 에이전트가 "스스로 판단"하는 지점을 적었다 (예: 충돌 찾기, 누구에게 물을지 정하기) | 5 |

## 2회차 – 범위 줄이기 (20점)

`02-scope.md`를 채웁니다. 힌트: 핵심 흐름은 "메시지 → 요구사항 표 → 충돌·질문 → (답변) → 근무표 + 설명" 하나.

| 채점 항목 | 점수 |
|---|---|
| 핵심 흐름이 5단계 이하이고 처음부터 끝까지 이어진다 | 5 |
| 안 만들 것 3개 이상 | 5 |
| 가짜로 처리할 부분을 표시했다 (예: 답변은 answers.md 로 흉내) | 5 |
| 시간 예산의 25% 이상을 검증·피칭에 남겼다 | 5 |

## 3회차 – 구현 준비

1. **완료 기준 3개를 직접 씁니다** (AI 없이). `03-criteria.md` 형식, 숫자 포함, 제3자가 예/아니오로 판정 가능.
   - 예시 방향(그대로 쓰지 말 것): "꼭 지킬 규칙 위반 0", "충돌을 찾고 근거를 세어서 댄다", "지어낸 요청 0"
2. 기준을 정한 다음에만 AI에게 구현을 맡깁니다 (practice_01 3회차 배움).
3. 실행 방식 선택: practice_01 에이전트처럼 **mock 모드(규칙)** 먼저 → 무료 모델은 그다음. `toolkit/starter/`나 `practice_01/agent/`를 참고해도 됩니다.

## 4회차 – 구현·검증

| 단계 | 할 일 | 결과물 |
|---|---|---|
| 4-1 | 요청·규칙을 읽어 **요구사항 표** 만들기 (출처·종류: 꼭 / 확정 요청 / 바람 / 애매) | `work/requirements.md` |
| 4-2 | **충돌**을 찾고 근거를 "세어서" 쓰기. 애매한 요청은 **누구에게 무엇을 물을지** 질문 만들기. 다 만든 뒤에야 `answers.md` 열기 | `work/conflicts.md`, `work/questions.md` |
| 4-3 | 답변을 반영해 **근무표**(`work/schedule.csv`, 형식은 아래)와 **설명**(배정마다 어떤 규칙·요청 때문인지, 못 지킨 요청은 누구에게 어떻게 말할지) 만들기. 그다음 `eval_hidden/`으로 채점 | `work/schedule.csv`, `work/explain.md`, 채점 결과 |

근무표 형식:
```
이름,월,화,수,목,금,토,일
가람,D,...
```
D=주간, E=저녁, N=야간, -=휴무

검증: `eval_hidden/check_schedule.py work/schedule.csv` (Colab에서는 파일 두 개를 올리고 `!python check_schedule.py schedule.csv`) + `eval_hidden/gold.md` 6절 채점표.

## 왜 이 문제인가 (류지웅 님 기준)
- 근무표 엔진(Timetable, timetable-ai)을 이미 만들어 본 경험을 쓸 수 있습니다.
- 공군 해커톤 "병영복지"·국방 Start-up 챌린지에서 **교대근무 조율**은 직접 겪은 문제로 쓸 수 있는 주제입니다. 단, 실제 부대 근무 정보는 넣지 않고 이렇게 일반화된 가짜 사례로 연습합니다.
